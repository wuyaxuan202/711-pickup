# 7-11 收件資料填寫表單

讓集資應援的贊助者填寫要取貨的 7-11 門市（店號、門市名稱、收件人姓名）。只有在贊助名單上、且「群組暱稱＋驗證資料」都正確的人才能送出。

## 架構

```
贊助者瀏覽器 ──► GitHub Pages（只有網頁，沒有任何個資）
                     │  HTTPS
                     ▼
              Google Apps Script（驗證身份、檢查格式）
                     │
                     ▼
              你私人的 Google 試算表（贊助名單、收件資料）
```

- GitHub 上**沒有任何名單或個資**，repo 公開也安全。
- 贊助名單只在你的試算表裡，從來不會傳到網頁上，別人看原始碼也拿不到。

## 安全設計

| 風險 | 怎麼處理 |
|---|---|
| 有人冒用別人暱稱 | 要暱稱＋驗證資料都對才能填；驗證在伺服器端 |
| 暴力猜驗證資料 | 同一暱稱錯 5 次鎖 30 分鐘；每次失敗刻意延遲 |
| 試探誰在名單上 | 暱稱錯、驗證資料錯都回同一句話，回應時間也一致 |
| 機器人灌單 | 隱藏陷阱欄位、全站每分鐘請求上限、內容大小上限 |
| 試算表公式注入 | 開頭是 `= + - @` 的內容會被轉成純文字；姓名、店名只允許文字 |
| 網頁被插入惡意程式 | 嚴格 CSP：只能載入自己的 JS、只能連到 Google Apps Script |
| 驗證資料外洩 | 只存在記憶體、送出後立刻清除，不寫 cookie／localStorage |
| 兩人同時送出 | 寫入時加鎖 |
| 被搜尋引擎收錄 | `noindex` |

## 設定步驟（約 10 分鐘）

### 1. 建立試算表與後端

1. 開一個新的 Google 試算表（**不要分享給任何人**）。
2. 上方選單「擴充功能」→「Apps Script」。
3. 把 `Code.gs` 的內容整個貼上，取代原本的程式碼，存檔。
4. 上方函式選單選 `setup`，按「執行」。第一次會要求授權，按允許。
   - 試算表會自動出現三個分頁：`贊助名單`、`收件資料`、`紀錄`。
5. 在 `贊助名單` 分頁填入贊助者：
   - A 欄：群組暱稱（跟群組裡顯示的一樣）
   - B 欄：驗證資料（例如匯款帳號末五碼）
   - 大小寫、前後空白、全形半形都會自動忽略。
6. （選填）要設截止時間：把 `Code.gs` 最上面的 `DEADLINE` 改成例如 `'2026-12-31T23:59:59+08:00'`。

### 2. 部署後端

1. Apps Script 右上「部署」→「新增部署作業」→ 類型選「網頁應用程式」。
2. 執行身分：**我**；誰可以存取：**所有人**。
   - 「所有人」是指任何人都能「呼叫」這個驗證服務，不是能看你的試算表。
3. 按部署，複製網址（結尾是 `/exec`）。

### 3. 設定網頁

打開 `config.js`：

- `API_URL` 換成剛剛複製的網址。
- `PROOF_HINT` 改成你要的說明，例如「請填寫贊助時的匯款帳號末五碼」。

### 4. 放上 GitHub Pages

1. 把整個資料夾推到 GitHub repo。
2. repo 的 Settings → Pages → Source 選 `Deploy from a branch`，Branch 選 `main`、資料夾選 `/ (root)`。
3. 等一兩分鐘，網址會是 `https://<你的帳號>.github.io/<repo名稱>/`。

### 5. 測試

用一筆自己加進名單的測試資料填一次，確認 `收件資料` 有寫入，再把測試那列刪掉。

## 日常使用

- **看結果**：直接看 `收件資料` 分頁。同一人重填會覆蓋，`修改次數` 會加一。
- **有人被鎖住**：等 30 分鐘就會自動解鎖。
- **補加贊助者**：直接在 `贊助名單` 新增一列，不用重新部署。
- **改了 Code.gs**：要到「部署」→「管理部署作業」→ 編輯 → 版本選「新版本」才會生效（網址不變）。
- **結束後**：到「管理部署作業」封存部署，表單就會停用。

## 注意

- 驗證資料不要在群組公開貼出，請一對一告訴贊助者「要填什麼」即可（例如只說「填你匯款帳號末五碼」）。
- 試算表裡有個資，活動結束、寄送完畢後建議刪除。
